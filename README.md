# 作业提交检查工具（AI 代写初筛）

给 Java 课程作业做**初筛**的小工具：读平台导出的 CSV，检查每次提交有没有
"直接复制粘贴"的痕迹，输出一份带证据的报告。

> ⚠️ 先说清楚定位：这不是"AI 检测器"，它检测的是**提交行为**，不是猜测代码作者。
> 结论分三档（不合格 / 复核 / 合格），"复核"的意思是**请老师找学生谈一次**。
> 工具只提供线索，最终结论必须由人来下。

---

## 一、目录结构

```
ai_homework_checker/
├── src/                        源码，9 个类
│   ├── Main.java               入口：串流程
│   ├── DataLoader.java         读 CSV（容错，报错清楚）
│   ├── Submission.java         一条提交记录
│   ├── CodeInfo.java           把源码拆成"代码区 / 注释区"
│   ├── Similarity.java         两份代码的相似度
│   ├── RuleEngine.java         所有规则和阈值都在这
│   ├── Finding.java            一条判定结果
│   ├── Evidence.java           一条证据
│   └── ReportWriter.java       输出 CSV / HTML 报告
├── data/
│   ├── submissions.csv         示例数据（模拟平台导出）
│   └── codes/                  示例代码文件
└── out/                        报告输出目录（运行后生成）
```

---

## 二、怎么跑（三步）

需要 JDK 8 及以上（开发时用的是 JDK 25）。

```powershell
# 1. 编译
cd ai_homework_checker
javac -encoding UTF-8 -d out src\*.java

# 2. 运行（用默认示例数据）
java -cp out Main

# 3. 看结果
#   控制台会打印摘要
#   out\report.csv  —— 可以用 Excel 打开
#   out\report.html —— 双击用浏览器打开，给老师看这个
```

指定自己的数据：

```powershell
java -cp out Main 我的导出.csv 我的输出目录
```

> 如果中文显示成乱码：那是 Windows 终端编码问题，**报告文件本身是 UTF-8，
> 用浏览器/Excel 打开是正常的**，不影响结果。

## 三、数据格式

### CSV 表头

列的顺序随意，中英文表头都认。最少需要这几列：

| 字段 | 中文表头也可写 | 必需 |
|---|---|---|
| studentId | 学号 | ✅ |
| name | 姓名 | |
| problemId | 题号 / 题目 | |
| submitTime | 提交时间 | ✅ |
| result | 判题结果 / 状态 | |
| codeFile | 代码文件 / 文件名 | ✅（或改用 code 列内联） |

```csv
studentId,name,problemId,submitTime,result,codeFile
2023001,张三,P1042,2026-10-12 03:14:22,AC,codes/2023001_P1042_1.java
```

支持的时间格式：`yyyy-MM-dd HH:mm:ss`、`yyyy/MM/dd HH:mm:ss`、
`yyyy-MM-dd'T'HH:mm:ss`、`yyyy-MM-dd HH:mm`。

### 关于代码

**强烈建议把代码存成单独文件**，在 CSV 里只写相对路径（相对 CSV 所在目录）。
把代码塞进 CSV 会因为里面的逗号、引号、换行导致解析失败——这是新手最常见的事故。

如果你的平台导出的是"每次提交代码都直接放在 CSV 的某一列"，那就得先写个小脚本
把代码拆成文件。这一列名为 `code` 也能被读取，但同样不支持字段内换行。

## 四、报告怎么读

### report.html

每个学生一行，三档结论：

- 🔴 **不合格** —— 有硬证据（代码里残留 AI 输出痕迹），或分数 ≥ 8
- 🟠 **复核** —— 有可疑迹象，需要谈一次
- 🟢 **合格** —— 没发现问题

带"硬证据"标签的条目，是可以直接拿去和学生说的那种证据。

### report.csv

同样内容，多一列"风险分"，方便排序和二次筛选。

## 五、规则与权重（都在 `RuleEngine.java` 顶部）

| 规则 | 权重 | 是否硬证据 | 说明 |
|---|---|---|---|
| ARTIFACT_PHRASE | 5 | ✅ | 注释里出现"以下是""希望对你有帮助""完整实现"等 AI 话术 |
| ARTIFACT_MARKDOWN | 5 | ✅ | 注释里出现 `**`、`###`、```` ``` ```` 等 Markdown 标记 |
| ARTIFACT_FENCE | 5 | ✅ | 代码里出现 Markdown 代码块围栏 |
| SPEED | 4 | ✅ | 两次提交间隔太短、新增字符太多，超过人手打上限 400 字符/分钟 |
| SIMILAR | 4 | | 与同题其他人代码相似度 ≥ 0.85 |
| FULLWIDTH | 3 | | 代码区出现全角括号/分号（中文输入法粘贴的典型痕迹） |
| UNUSED_IMPORT | 1 | | 有 import 但代码里没用 |
| SINGLE_SUBMIT | 1 | | 该题只提交 1 次（**弱信号**，本地写好再上传也会这样） |
| JAVADOC_ALL | 1 | | 每个方法都带 Javadoc，完整度超出课程作业常见水平 |

判定规则：

```
有硬证据            → 不合格
分数 ≥ 8            → 不合格
分数 ≥ 3            → 复核
其余                → 合格
```

**调阈值的正确姿势**：不要凭感觉改。先拿一个班的数据跑一遍，人工核对
"不合格"和"复核"的人，数一数冤枉了几个、漏了几个，再回来调 `RuleEngine`
顶部的常量。

## 六、接真实数据要做的事

1. 从平台导出提交记录（至少要有：学号、提交时间、代码）
2. 把每次提交的代码存成独立文件，命名建议 `学号_题号_第几次.java`
3. 用 Excel 整理成 CSV（另存为 **CSV UTF-8**，不要存成 GBK）
4. 表头改成上面的格式，`codeFile` 填相对路径
5. 运行，看报告，人工核对，调阈值

如果平台**能记录粘贴事件**（粘贴了多少字符、什么时候粘的），一定让老师加上。
那是最硬的证据，能直接把"复核"坐实成"不合格"，比这套静态规则可靠得多。

---

## 七、已知局限（这一段建议原样写进报告，是加分项）

1. **本地写好再粘贴的正常学生会拿到 1 分**（SINGLE_SUBMIT），但不会因此判不合格。
   这是刻意的：弱信号只累加、不定罪。
2. **改写过的 AI 代码检测不到**。变量名一换、注释一删，规则基本失效。
3. **相似度不区分"抄同学"和"都抄 AI"**。对老师来说结论一样（都没有独立思考），
   但报告措辞上不应该说成"抄袭"。
4. **不打分、不判卷**，只看提交过程。代码写得对不对不在本工具职责内。
5. 相似度用 5-gram + Jaccard，属于轻量方案。样本量大（几百人以上）时建议换成
   JPlag，它有多机审校和抗混淆能力。

## 八、验证方式

拿本工具跑一遍示例数据（8 个学生、12 次提交），结果应当为：

| 学生 | 结论 | 触发原因（示例） |
|---|---|---|
| 张三 | 不合格 | 注释含"以下是完整的实现" |
| 郑十 | 不合格 | 1.2 分钟内新增 996 字符 + 与 3 人同源 |
| 王五 | 复核 | 与 3 人同源、全部方法带 Javadoc |
| 赵六 | 复核 | 与 3 人同源 |
| 孙七 | 复核 | 全角标点（CE 那一次） |
| 李四 | 合格 | 3 次提交，有 CE→WA→AC 的完整迭代 |
| 周八 | 合格 | 2 次提交，有修正过程 |
| 吴九 | 合格 | 风格自成一派，与其他人相似度低 |

这个示例集是专门设计的"标准答案"，改完代码后跑一遍，结果和上表一致
说明你的改动没有破坏原有逻辑。
